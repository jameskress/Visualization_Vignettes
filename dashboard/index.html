How to read this
Upgrade table
how much each vignette's time changed between two tool versions on each machine, from runs of the same vignette code. Colour means the change is real: at least 10%, and a Welch t-test on the repeated runs says it is unlikely to be noise.
Blue, red
in the upgrade table, blue is faster with the newer version and red slower; in the every-machine grid, blue is below the typical run and red above. Darker is a bigger change. An uncoloured number is within the noise, and a dotted one had a single run, so it cannot be told from noise yet.
Every machine, every version
each machine at each tool version against the typical run (1x): per vignette, the median over every machine and version, fixed at a stated date. 1.25x is 25% more time (or memory or energy), 0.8x is 20% less. Coloured only when the repeated runs say it is beyond the noise.
Run history
on vignette and machine pages, x is the machine's own run number, colour and shape the tool version. Hollow: not comparable with the latest run (older vignette code, or measured differently). A dashed amber line: the OS, kernel or GPU driver changed.
✓ ✗
pass / fail over every comparison gate (image, numbers, CSV); ● ○ for older runs that only say whether the vignette finished. Stale: no run in 183 days, or the last run used an older version than the one the suite tests by default.

How the index is computed
Which runs
Only runs of each vignette's newest code, so every run compared measured the same test, and only runs that finished.
Typical run
The baseline for every number and colour here. Per vignette: each machine-and-version's median, then the median of those. It is computed from the records up to the stated date and kept there, so a new machine or run does not move every cell; it is moved on purpose, at a release. A measure or vignette with no records before that date uses all of them, and says so.
Cell, all vignettes
The geometric mean, over the vignettes, of the machine's median divided by the typical run, so each vignette counts the same whatever its length. A row is averaged over the vignettes of its most complete version; a version that lacks some is marked with a corner tick and covers only the ones it has. Each machine keeps to one way of measuring (its latest record's), so a change of method is never read as a change between versions.
Colour
Only when the change is beyond the noise: resampling each vignette's repeated runs 300 times gives a 95% range, and the cell is coloured when that range leaves out 1× and the cell is at least 5% from it. A dotted number had one run per vignette, so its noise is unknown.
Peak memory
Only runs measured as PSS, the memory the processes doing the work hold, which means the same on every machine. Slurm-sampled memory is left out.
Energy
Node energy where the node's own counters are readable (Shaheen CPU nodes); GPU energy, the GPUs alone, wherever nvidia-smi is.
