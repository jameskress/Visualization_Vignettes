ParaView

ParaView ex00 Query

Prints facts about a dataset instead of drawing it; the printout is compared line by line with a saved copy. Results · source

Reads
Nothing: it makes a cone.
Does
Prints the cone's resolution, height, radius, centre and direction, then the OpenGL driver ParaView is using.
Writes
Text only, no image.
Checked
The printout is compared line by line with a saved copy, which names an NVIDIA driver, so a run with --non_gpu_machine reports a failure only as a warning.

No image: this vignette checks numbers.

ParaView ex06 Large data (+3 site-specific sets)

A 5.7 GB cyclone simulation drawn as slices, terrain, volume rendering and wind, in parallel. Results · source

Reads
A WRF simulation of Cyclone Chapala (2015) and a rainfall file, 5.7 GB together; skipped where the data is not installed.
Does
Slices coloured by water vapour; terrain raised by height; rain and ice volume-rendered; surface wind as line-integral convolution (a streaky texture that follows the flow) with arrows; rainfall on top. Rendered in parallel with OSPRay (the batch scripts use 8 ranks).
Writes

Checked

ParaView ex07 Scaling

Extracts and measures one isosurface at any number of ranks; the measurements must not change with the rank count. Results · source

Reads
The 20-step varying series (a 50 × 50 × 50 grid; the field temp), as legacy .vtk files.
Does
At each step, contours temp at 3.0 and integrates the contour to get its area; reading, contouring, integrating and rendering are timed separately. A rank is one MPI process; this runs at any count.
Writes
One PNG of the last isosurface and a row of timings.
Checked
The last step's numbers must match the baseline at every rank count: 20 steps read, 125 000 points, 5386 contour cells, contour area 303.84, temp range 1.93 to 26.10. The timings are recorded, not compared.

ParaView ex08 Backend check

Fails when a job that asked for a GPU renders in software. Results · source

Reads
Nothing: it makes a sphere.
Does
Asks the OpenGL driver who it is (vendor, renderer, version) and calls it software (llvmpipe, swrast and similar) or hardware (NVIDIA, AMD, Intel); then renders a small probe image.
Writes
One probe PNG; the driver strings go into the record's notes.
Checked
A job that asked for a GPU (EGL) must get hardware, one that asked for OSMesa must get software, and the probe must be the requested size.

ParaView ex09 Mesh topologies

The same contour over four kinds of mesh; the point, cell and contour counts of each are checked. Results · source

Reads
Four generated meshes of the same wave field: a tetrahedral mesh, an adaptive-refinement (AMR) mesh, a polygonal surface, and a grid split into three blocks of unequal width.
Does
Contours each one (the surface as white isolines over its colours), removes AMR ghost cells (the overlap between refinement levels) and merges the blocks first.
Writes
Four PNGs, one per mesh, and a table of counts.
Checked
Per mesh: input points and cells, contour cells and value range against the baseline, and the blocks must really be unequal.

ParaView ex10 Colormap fidelity

One field through four colour maps (built in, custom, logarithmic, categorical), each with its legend. Results · source

Reads
One step of the varying series (temp, 1.78 to 27.40).
Does
Draws temp four ways: a built-in map (Cool to Warm Extended), a custom map loaded from an XML file, the custom map on a log scale, and five labelled categories (coolest to warmest). The legend's font, position and number format are fixed.
Writes
Four PNGs and a table of the settings applied.
Checked
Per map: the range, log scale on or off, categories on or off and the legend shown; the images against their baselines.

ParaView ex11 State verification

A saved session reloaded without a GUI and stepped through three time steps. Results · source

Reads
A saved ParaView state file (.pvsm): the varying series contoured at 3.0.
Does
Loads the state without the GUI, points it at this machine's data, steps through three time steps and disconnects.
Writes
Three PNGs, one per step.
Checked
The state holds two sources, one 1024 × 1024 view and 20 time steps; all three steps render, time advances, and the session closes cleanly.

ParaView ex12 Extract regression

Writes three kinds of output per time step (contour geometry, an image and a row of measurements) and checks each one against its baseline. Results · source

Reads
The 20-step varying series (a 50 × 50 × 50 grid; the field temp), as a .pvd file.
Does
At each of three time steps, contours temp at 3.0 and integrates the contour (its area) and the grid (the mean of temp). An extract is a file written as the pipeline runs: here the contour geometry, an image, and a row of measurements.
Writes
Per step one .vtp contour and one PNG, plus one CSV with a row per step: time step, cycle, time, input points and cells, contour points and cells, contour area, and the minimum, maximum and mean of temp.
Checked
Every CSV cell against the baseline table (relative tolerance 10⁻⁶), the images against theirs, one file of each kind per step, and positive areas.

VisIt ex12 Extract regression

Writes three kinds of output per time step (contour geometry, an image and a row of measurements) and checks each one against its baseline. Results · source

Reads
The 20-step varying series (a 50 × 50 × 50 grid; the field temp), as a .visit file.
Does
At each of three states: an isosurface at 3.0, exported as a VTK file; an image; and queries for the counts, area and range. A second plot without the operator sums temp over the volume for the mean.
Writes
Per step one exported contour and one PNG, plus one CSV with the same columns as ParaView and the weighted sum and volume.
Checked
Every CSV cell against the baseline table (relative tolerance 10⁻⁶), the images, one file of each kind per step, and a distinct time for every state. Clear output/ first: older exported files are counted too.
